# 3DS 한글패치 매니저

[Translation Toolkit](https://github.com/Ich73/TranslationToolkit)의 로컬 포크에 추가한 한국어 데스크톱 도구입니다. 원본 기준 커밋은 `d1719d8e6cc659bf423f227a0218aed6e60af496`이며 기존 Toolkit과 GPL-3.0 라이선스를 보존합니다. GitHub 계정에 게시된 포크는 아닙니다.

## 실행과 준비

Windows 배포 폴더에는 Python·Tkinter, xdelta와 RomForge 실행 환경이 포함되어 있습니다. 압축을 모두 푼 뒤 폴더 맨 위의 `3DS 한글패치 매니저 실행.bat`를 실행하세요. 폴더 전체를 함께 이동해야 합니다. 게임 파일과 필요한 키는 별도로 준비합니다.

소스에서 직접 실행하려면 Python 3.10 이상과 Tkinter가 필요합니다. 이 폴더의 `3DS 한글패치 매니저 실행.bat` 또는 `python KoreanPatchManager.py`로 실행합니다. 소스 실행 시 RomForge 추출·리팩에는 .NET 10 런타임과 로컬 RomForge 포크의 브리지가 필요합니다. 브리지를 빌드하려면 .NET 10 SDK와 NuGet 접근이 필요하며 **RomForge 브리지 빌드** 버튼을 사용하세요.

## 초간단 모드 (처음 화면)

처음 실행하면 **초간단 모드**가 열립니다. 패치를 받아서 쓰는 사람을 위한 화면이며, 글자를 입력하는 칸이 없습니다.

1. 받은 패치 ZIP을 창에 끌어다 놓습니다(창을 눌러 고를 수도 있습니다). 압축을 푼 폴더를 놓아도 됩니다.
2. **닌텐도 3DS**와 **PC** 중 플레이할 곳을 고릅니다.
3. **시작**을 누릅니다.

프로그램이 ZIP 안을 보고 종류를 알아내므로 사용자가 패치 종류를 고르지 않습니다.

| 넣은 패치 | 추가로 필요한 것 | 3DS를 고르면 | PC를 고르면 |
|---|---|---|---|
| 설치용 ZIP (`luma/titles/…` 또는 `load/mods/…`) | 없음 | SD 카드의 `luma/titles/<Title ID>`에 복사 | 에뮬레이터 폴더의 `load/mods/<Title ID>`에 복사 |
| 통합 패키지 (`kpm-merge-v1`) | 본편 게임 파일 | 설치용 `.cia` 생성 (키 폴더 필요, 게임이 CIA면 `certs.bin`은 불필요) | `.cci` 생성 |
| 일반 xdelta 패키지 (`kpm-xdelta-v2`) | 본편 게임 파일 | 게임에서 패치 파일을 되살려 SD 카드에 복사 | 같은 파일을 에뮬레이터 폴더에 복사 |
| 레시피 패치 (`kpm-recipe-v1`, 0.4.0~) | 패치가 요구하는 본편·업데이트(·DLC) | 「패치 설치」: SD 카드에 설치 / 「합본 게임 파일」: `.cia` 생성 (키 폴더 필요) | 「패치 설치」: 에뮬레이터 폴더에 설치 / 「합본 게임 파일」: `.3ds` 생성 |

- 게임 파일을 넣는 즉시 헤더의 Title ID를 패치와 비교합니다. 다른 지역의 게임이나 업데이트 파일은 그 자리에서 알려 줍니다. 파일 내용의 일치 여부는 작업 중 파일별 해시로 확인합니다.
- SD 카드는 이동식 드라이브에서 자동으로 찾고, Azahar·Lime3DS·Citra 사용자 폴더도 자동으로 찾습니다. 찾지 못하면 폴더를 직접 고릅니다.
- 같은 패치가 이미 들어 있으면 아무것도 바꾸지 않습니다. 다른 내용이 들어 있으면 먼저 물어본 뒤 기존 폴더를 `luma/titles_backup`(에뮬레이터는 `load/mods_backup`)으로 옮기고 새로 설치합니다. 지우는 파일은 없습니다.
- 복사할 파일은 대상 폴더 옆에 먼저 모두 풀어 CRC를 확인한 다음 폴더째 바꿉니다. 중간에 실패하면 원래 상태로 되돌립니다. 정션이나 심볼릭 링크로 연결된 설치 폴더에는 설치하지 않습니다.
- 만든 게임 파일은 원본 옆에 `이름 [한글패치].cci`처럼 저장합니다. 원본과 패치 파일은 바꾸지 않습니다.
- 키 폴더와 마지막으로 고른 곳은 `%APPDATA%\KoreanPatchManager\easy.json`에 기억합니다. 프로그램 폴더 옆에 `keys` 폴더를 두면 자동으로 찾습니다.
- Windows의 밝은·어두운 앱 테마를 따르며, 화면 배율이 높은 모니터에서도 글자가 흐려지지 않습니다. Enter는 시작, Esc는 뒤로, F1은 도움말입니다.

오른쪽 위 **제작자 도구**를 누르면 아래의 간편 모드와 전체 모드로 갑니다. 그 화면의 **← 초간단 모드** 버튼으로 돌아옵니다.

초간단 모드의 화면은 표준 라이브러리만으로 그립니다. 둥근 카드와 버튼은 `korean_patch_manager/paint.py`가 PNG로 만들고, 파일 끌어다 놓기는 `dnd.py`가 Windows 메시지로 받습니다. 패치 인식과 설치는 화면과 분리된 `easy.py`에 있습니다. 끌어다 놓기와 SD 카드 찾기는 Windows에서만 동작하며 다른 환경에서는 파일 고르기를 씁니다. 이 화면은 Tab 키 이동과 화면 낭독기를 지원하지 않으므로 필요하면 간편 모드를 쓰세요.

## 레시피 패치 (내 게임 파일로 만드는 패치, 0.4.0~)

게임 데이터를 하나도 담지 않은 작은 패치 ZIP입니다. 번역문, 제작자가 그린 글자, 바꿀 바이트와 해시만 들어 있고,
게임마다 정해진 엔진(`korean_patch_manager/games/<엔진>/`)이 사용자의 복호화된 게임 파일로 이 PC에서 패치를 만듭니다.

1. 레시피 ZIP과 본인 게임 파일(본편·업데이트, 원하면 DLC)을 한꺼번에 끌어다 놓습니다. Title ID를 보고 알아서 자리에 넣습니다.
2. **무엇을 만들까요?**에서 고릅니다.
   - **패치 설치**(추천): 만든 `code.ips`·`romfs/`를 설치용 ZIP과 똑같이 SD 카드나 에뮬레이터 폴더에 넣습니다. DLC는 쓰지 않습니다.
   - **합본 게임 파일**: 본편+업데이트(+DLC)+패치를 하나로 만듭니다. PC는 `.3ds`, 3DS는 `.cia`(RomForge 브리지로 변환, 키 폴더 필요)입니다. 작업 중 약 13GB가 필요합니다.
3. 플레이할 곳을 고르고 시작합니다.

- 원본 파일과 결과 파일을 레시피에 적힌 해시와 대조합니다. 다른 지역·버전이거나 암호화된 파일은 넣는 순간 알려 줍니다.
- 패치 코드가 Luma3DS가 LayeredFS를 켤 때 자기 코드를 쓰는 자리(.text 끝, 약 0x114바이트)와 겹치면 설치하지 않습니다. 이 자리에 쓴 코드는 에뮬레이터에서는 동작해도 실기에서 게임을 멈추게 합니다.
- 합본 `.cia`는 검사한 `.3ds`와 게임 내용(첫 콘텐츠)이 바이트 단위로 같은지 확인한 뒤 저장합니다. 결과 옆에 `<이름>.검증.json`을 남깁니다.
- 합본을 쓸 때는 같은 게임의 공식 업데이트를 지우거나 끄세요. 설치된 업데이트가 있으면 그쪽 실행 코드가 쓰입니다.
- 합본은 3dstool 1.2.6(MIT, `app/tools/3dstool-1.2.6`)으로 만듭니다.
- 지원 엔진: `ssb3ds` (대난투 스매시브라더스 for Nintendo 3DS 한국판 + 업데이트 1.1.7, DLC 선택). 엔진은 각 게임의 한글 패치 프로젝트에서 관리하고 이 저장소에는 복사본(`SOURCE.json`에 해시)을 둡니다.

## 간편 모드와 전체 모드

**간편 모드**는 할 일 고르기 → 파일 고르기 → 시작하기 순서로 진행하며, 선택한 작업의 입력만 표시합니다. 받은 통합 패키지는 본편과 패키지·저장 위치를 고르면 작업 폴더를 자동으로 준비해 적용합니다. PC에서 사용을 고르면 CCI, 3DS에 설치를 고르면 CIA를 만듭니다. CCI에서는 키 없이 시도할 수 있고, CIA에서는 키 폴더가 추가로 나타납니다. 넣은 게임 파일이 CIA이면 그 안의 인증서를 쓰므로 `certs.bin`을 따로 준비하지 않아도 됩니다. **준비 방법** 버튼은 게임·키·인증서의 추출 절차와 원문 링크를 보여 줍니다. 작업 기록은 필요할 때 펼칠 수 있습니다.

상단 목록에서 **전체 모드**로 바꾸면 기존 제작·리팩·전송 기능과 프로젝트 저장을 사용할 수 있습니다. 입력 항목 옆 **?** 또는 **도움말(F1)**로 설명을 확인하세요. 전체 모드의 **처음 시작** 탭에서 초록색은 경로나 기본 파일이 있다는 뜻이고 주황색은 준비할 항목입니다. 파일 존재 확인은 호환성이나 게임 실행 성공을 보장하지 않습니다.

파일별 xdelta 생성과 적용은 xdelta3가 필요합니다. Windows x64에서는 **xdelta 설치** 버튼이 공식 3.2.2 배포판을 내려받아 SHA-256을 확인하고 로컬 `tools`에 설치합니다. 다른 플랫폼에서는 별도로 설치한 실행 파일을 선택하세요. xdelta 3.2.2는 Apache-2.0으로 제공되며 [소스 및 릴리스](https://github.com/jmacd/xdelta/releases/tag/v3.2.2)를 참조하세요. 이 도구는 게임 데이터나 암호화 키를 제공하지 않습니다.

## 패치 제작과 배포

1. 직접 보유한 게임과 필요한 개인 키 파일을 준비합니다. **RomForge 리팩** 탭에서 키 폴더를 고른 뒤 **원본 게임에서 번역 작업 폴더 준비**를 누르면 RomFS 원본, 편집용 복사본, 가능한 경우 압축을 해제한 원본 코드, `project.json`을 생성하고 프로젝트를 불러옵니다. CCI/3DS, CIA, ZCCI를 지원합니다. 다른 도구로 추출한 RomFS를 직접 지정해도 됩니다. Kuriimu2 등으로 편집용 복사본을 수정하되 같은 상대 경로를 유지하고, 서로 다른 게임이나 업데이트의 RomFS를 섞지 마세요.
2. 원본·수정 RomFS, Title ID, 지역과 본편/업데이트 버전을 지정합니다. **게임 파일 정보 읽기**는 CIA의 TMD 또는 CCI/3DS·NCCH 헤더에서 Title ID를 읽습니다. CIA는 TMD 버전도 표시합니다. 읽은 값은 서명 검증을 거친 값이 아니며 CCI의 업데이트 버전과 지역을 알려주지 않습니다. 업데이트 CIA의 ID는 본편 ID와 다를 수 있으므로 본편에 적용할 패치를 만들 때는 본편 파일을 선택하세요. 이 버튼은 ZCCI 헤더를 해석하지 못하지만, RomForge 작업 폴더 준비와 리팩에서는 ZCCI의 Title ID를 확인합니다.
3. 원본 게임 파일을 지정하면 Title ID가 입력값과 일치하는지 검사하고 SHA-256을 기록합니다. `code.ips`와 압축 해제된 원본 코드도 선택할 수 있습니다. 프로젝트 설정은 JSON에 저장할 수 있으며 FTP 암호는 저장하지 않습니다.
4. **변경 분석**을 실행합니다. 추가 파일은 지원하지만 삭제는 LayeredFS로 표현하지 못해 빌드를 중단합니다. **IPS 간 충돌 검사**는 여러 IPS 파일의 기록 주소가 겹치는지 검사합니다. 원본 코드를 선택하면 패치 범위도 검사합니다.
5. 빈 출력 폴더에서 **Luma / Azahar ZIP 생성**을 누르면 `luma.zip`, `azahar.zip` 및 해시 매니페스트가 생성됩니다. 수정 파일의 전체 내용이 들어가므로 배포 전 포함 파일을 확인하세요.
6. Luma ZIP은 SD 카드 루트에 풀고 Luma의 Game Patching을 켭니다. Azahar ZIP은 사용자 데이터 폴더에 풉니다. 직접 전송 탭의 Azahar 설치는 기존 파일과 겹치지 않는 경우 병합하며 다른 내용의 파일이나 기존 코드 패치와 충돌하면 중단합니다. FTP 전송은 기존 Title ID 폴더가 없을 때만 진행합니다. FTP 실패 시 실기에 부분 파일이 남을 수 있고 전송 내용이 암호화되지 않습니다.

## xdelta 패키지와 사용자 적용

**xdelta 생성**은 변경 파일을 각각 패치하고 복원해 SHA-256을 검증합니다. 새 파일은 전체 내용으로 ZIP에 들어가며 삭제는 지원하지 않습니다. 코드 패치만 담는 것도 가능합니다. ZIP에는 각 파일의 원본·결과 해시와 선택한 게임·코드 해시가 기록됩니다.

사용자는 원본 RomFS와 xdelta 실행 파일을 선택한 후 **xdelta 적용**으로 패키지를 엽니다. 각 원본과 복원 결과를 해시로 검사하고 `restored_patch` 및 설치용 ZIP이 들어 있는 `restored_packages`를 선택 폴더 아래 생성합니다. 게임 파일 또는 원본 코드를 선택하면 패키지에 기록된 전체 해시와 추가로 비교합니다. 선택하지 않은 전체 파일의 일치 여부는 보장하지 않습니다. 같은 이름의 결과 폴더가 이미 있으면 다른 위치를 선택하세요. 이 ZIP은 이 GUI의 전용 형식입니다.

## 본편 + 업데이트 + 번역 통합 패키지

**업데이트 통합** 탭은 본편에 업데이트와 번역을 합쳐야 하는 게임을 위한 기능입니다.

1. 프로젝트 탭에서 본편 게임을 선택하고 RomForge 리팩 탭의 키 폴더를 지정한 뒤 **원본 게임에서 번역 작업 폴더 준비**를 실행합니다. 업데이트 CIA도 같은 방법으로 별도 작업 폴더를 만듭니다. 같은 상위 폴더를 고르면 이름에 번호가 붙습니다. 두 작업 폴더는 각각 통합 탭에 자동으로 들어갑니다. 이전 버전에서 준비한 폴더에는 원본 해시 기록이나 확장 헤더가 없으므로 다시 만들어야 합니다.
2. 번역 패치 RomFS 폴더에는 원본 전체가 아니라 **변경 파일만** 선택할 수 있습니다. 우선순위는 `본편 → 업데이트 → 번역 패치`입니다. 업데이트 코드에 적용할 IPS와 HOME 배너를 선택할 수 있습니다. **HOME 메뉴 한국어 이름**을 적으면 본편 아이콘(SMDH)의 한국어 칸만 그 이름으로 바꿔 패키지에 담습니다. 한글 이름은 시스템 글꼴에 한글이 있는 한국어 본체에서만 보입니다. 그림까지 바꾼 아이콘 파일이 있으면 이름 대신 **교체 아이콘 SMDH**로 지정합니다. 이전 버전에서 준비한 본편 작업 폴더에는 원본 아이콘이 없으므로 이름을 넣으려면 다시 준비해야 합니다. IPS를 빼면 업데이트 코드 그대로 사용합니다. 별도의 60fps 관련 RomFS 파일이 번역 폴더에 포함돼 있다면 IPS만 빼도 그 파일은 남습니다.
3. **본편 기준 통합 xdelta 패키지 생성**을 누릅니다. 변경된 RomFS, 실행 코드, 확장 헤더 및 선택한 배너·아이콘이 본편 기준 차분으로 저장됩니다. 새 파일 추가나 파일 삭제, 코드 영역의 메모리 배치 또는 권한이 달라지는 업데이트는 안전을 위해 거부합니다. 이 ZIP은 매니저 전용 형식이며 RomForge 앱에서 바로 읽는 ZIP이 아닙니다.
3DS용 통합 CIA는 통합한 업데이트의 버전 번호를 그대로 가집니다. HOME 메뉴는 설치된 버전을 서버에서 받은 최신 업데이트 번호와 비교하므로, 이 번호가 본편 그대로(0)이면 공식 업데이트를 지운 상태에서 게임을 켤 때마다 업데이트를 요구합니다. 툴은 업데이트 CIA의 TMD 버전을 쓰고, 덤프에 0이 들어 있으면 업데이트의 리마스터 버전(확장 헤더 0x0E)으로 `(리마스터 × 1024) + 1023`을 씁니다. 정확한 번호를 알면 `merge.build_bundle(..., title_version=번호)`로 패키지에 기록할 수 있습니다.

4. 받는 사람은 자신의 본편에서 만든 작업 폴더와 게임 파일, 키 폴더 및 xdelta를 지정하고 **통합 패키지를 본편에 적용 및 리팩**을 사용합니다. 입력 파일과 출력 파일의 SHA-256을 검증하며 CIA·CCI·ZCCI를 생성합니다. 원본 게임, 키, 추출 파일, 임시 리팩 데이터가 사용자 컴퓨터에 있어야 합니다. 복호화된 CIA 콘텐츠를 읽는 데는 공통 키가 필요 없고, 암호화된 콘텐츠나 CIA 출력에는 해당 키가 필요합니다.

이 방식이 모든 게임이나 업데이트에 맞는 것은 아닙니다. IPS는 원본 코드의 해시를 자체적으로 포함하지 않으므로, 선택한 IPS가 해당 업데이트 버전용인지 제작자가 확인해야 합니다. 원본 해시 기록은 추출 후 우발적인 파일 변경을 감지하며 게임 버전의 공식 인증은 아닙니다. 공식 업데이트가 설치되어 있으면 별도 업데이트의 코드와 파일이 통합 본편보다 우선될 수 있습니다. 특히 마리오&루이지 RPG3 DX 일본판 v1.2의 시험은 공식 업데이트 없이 진행됐습니다. 업데이트 설치 상태 변경이나 실제 기기에서의 설치·실행은 이 도구가 수행하거나 검증하지 않습니다.

## RomForge로 직접 리팩

프로젝트 탭에서 게임 파일과 원본·수정 RomFS를 지정하고, **RomForge 리팩** 탭에서 개인 키 폴더와 출력 형식을 선택하세요. **원본 게임에 패치 적용 및 리팩**은 RomForge 엔진을 호출해 CCI, CIA, ZCCI를 생성합니다. 엔진에 넘기기 전 게임 내부의 변경 대상 원본 파일을 SHA-256으로 비교하고, 리팩 후 해당 파일과 code.ips 적용 결과를 다시 읽어 검증합니다. 출력 파일은 검증 후에만 지정 경로에 저장하며 기존 파일을 덮어쓰지 않습니다.

**xdelta 패키지를 게임에 적용 및 리팩**은 이 매니저의 xdelta ZIP과 원본 RomFS·게임 파일을 입력받아 같은 과정을 수행합니다. 패키지에 원본 게임 SHA-256이나 코드 SHA-256이 있으면 게임에 대조합니다. 새로 추가한 파일과 파일 삭제는 이 리팩 경로에서 지원하지 않습니다.

CIA 입력을 CIA로 출력할 때 버전을 비워두면 원본 CIA의 TMD 버전을 유지합니다. CCI/3DS/ZCCI에서 CIA를 만들 때는 TMD 버전 숫자를 입력해야 합니다. 예를 들어 v1.0.0은 0이며, v1.1.2는 1042입니다. 버전 숫자는 `(major × 1024) + (minor × 16) + micro`입니다. 업데이트·DLC CIA 생성은 RomForge 엔진이 지원하지 않습니다. CIA 생성에는 키 폴더에 `certs.bin`과 필요한 키가 있어야 합니다. 키는 도구가 제공하지 않습니다.

RomForge 엔진은 변경 대상 파일을 검증하지만 나머지 모든 게임 데이터의 무결성, 실제 설치·실행, 폰트 표시 또는 게임 진행을 보장하지 않습니다. 저장 공간은 원본 RomFS와 편집 복사본, 임시 리팩 결과를 담을 만큼 필요합니다.

## RomForge ZIP

**RomForge ZIP**은 [RomForge의 3DS 리팩 문서](https://github.com/sinjunyoung/RomForge/blob/main/docs/3ds-merge.md)에 맞춰 `romfs/...`와 선택적인 루트 `code.ips`를 생성합니다. RomForge의 **3DS - 리팩**에서 패치 ZIP으로 선택하세요. 현재 생성하는 ZIP에는 변경된 전체 파일이 들어가며, 기존 파일에 대한 교체만 지원합니다. 새 파일, 삭제 및 RomForge가 패치 확장자로 해석하는 파일이 있으면 생성을 중단합니다. 합성 게임 이미지로 직접 리팩 결과를 검증했으며 실제 게임과 실기에서는 별도 확인이 필요합니다.

## 기존 Translation Toolkit

**기존 Toolkit CLI 실행**을 누르고 `.ttparams`를 포함하는 번역 작업 폴더를 선택하면 해당 폴더에서 원본 CLI가 별도 콘솔로 실행됩니다. AP, CP, D, S, SC, RP, EG, RG, SW, UW 등은 [원본 README](README.md)를 참조하세요. RomForge 기반 추출·리팩은 위의 별도 브리지를 통해 제공됩니다. 원본 CLI의 EG/RG는 게임별 조건과 외부 도구에 의존하며 외부 다운로드를 수행할 수 있습니다.

## 검증 범위

- 헤더에 기록된 Title ID와 CIA TMD 버전을 확인하지만 지역, 실제 설치된 업데이트와 게임 호환성은 확인하지 않습니다. ZCCI를 일반 분석할 때는 파일 해시만 기록하고, RomForge 추출·리팩 시 Title ID를 검사합니다. 해시는 본인이 지정한 원본을 기준으로 기록하고 비교하며 공식 데이터베이스에 대조하지 않습니다.
- IPS 검사 통과는 코드 내용의 호환성이나 게임에서 정상적으로 로드됨을 뜻하지 않습니다. 겹치는 IPS 기록은 같은 값을 쓰더라도 잠재적 충돌로 보고합니다.
- GUI의 생성·복원과 직접 설치는 원본 폴더를 변경하지 않습니다. 게임 실행은 Azahar와 실기에서 별도로 테스트해야 합니다.
- 실제 사용자의 암호화 게임, 키, Azahar, 실기에서는 아직 검증하지 않았습니다. RomForge ZIP 및 생성된 게임은 대상 버전과 실행을 각각 확인해야 합니다.

## 개발 검사

`python -m unittest discover -s tests -v`로 기본 검사를 실행합니다. 레시피 실데이터 검사(`tests/test_recipe.py`)는 `KPM_TEST_SSB3DS`에 레시피 ZIP과 본인의 복호화 덤프가 든 폴더를 지정할 때만 실행합니다. 창을 띄우는 검사는 `KPM_TEST_GUI=1`일 때만 실행하며, 초간단 모드 검사(`tests/test_easy_ui.py`)는 실제 창에 마우스·키보드·파일 놓기 이벤트를 보냅니다. 실제 xdelta를 테스트하려면 `KPM_TEST_XDELTA` 환경 변수에 실행 파일 경로를 설정하세요. `pyftpdlib`가 설치되어 있으면 로컬 FTP 서버 통합 검사도 실행합니다. 이 두 항목은 선택적 테스트 의존성이며 GUI 실행에는 필요하지 않습니다.

RomForge 브리지의 코드와 빌드 설명은 [로컬 포크](../../RomForge-reference/README_KPM.md)에 있습니다. 합성 테스트는 .NET 브리지와 `KPM_TEST_ROMFORGE_BRIDGE`, `KPM_TEST_ROMFORGE_FIXTURE` 환경 변수가 필요합니다.
